# BLOCK STACKER — 테트리스형 블록 낙하 퍼즐

설치·빌드·서버·외부 라이브러리 없이 **HTML · CSS · 순수 JavaScript**만으로 브라우저에서 바로 실행되는 블록 낙하 퍼즐입니다.

- **화면:** 랜딩 페이지(`index.html`)에서 플레이 방법을 보고 **플레이**를 누르면 게임(`game.html`)이 바로 시작됩니다.
- **디자인:** Material Design 3(M3) 다크 테마를 라이브러리 없이 CSS로 직접 적용했습니다.
- **배경음악:** 이 게임용으로 새로 쓴 곡 2개를 WebAudio API로 실시간 합성합니다. 일시정지 화면에서 곡을 바꿀 수 있고, 음악 파일은 없습니다.
- **모바일:** 휴대폰 화면에 맞게 배치가 바뀌고, 보드 위 스와이프와 화면 아래 버튼으로 플레이합니다.

## 실행하고 접속하기

필요한 것은 **최신 브라우저 하나**입니다(Chrome, Edge, Firefox, Safari). 설치할 패키지도, 빌드 단계도 없습니다. 어떤 방법이든 **`index.html`(랜딩)** 을 열고 **플레이**를 누르면 됩니다.

| 방법 | 언제 쓰나 | 주소창에 보이는 것 |
| --- | --- | --- |
| A. 파일 바로 열기 | PC에서 혼자 플레이할 때 (가장 간단) | `file:///.../index.html` |
| B. 로컬 서버 | 개발·디버깅할 때, 서버로 서비스하는 상황을 흉내 낼 때 | `http://localhost:8000` |
| C. 휴대폰 접속 | 휴대폰에서 실제로 플레이할 때 | `http://<PC의 IP>:8000` |

> **왜 서버 없이도 돌아가나?** 브라우저는 `file://`로 연 페이지에서 `fetch()`와 ES 모듈(`type="module"`) 로딩을 보안상 막습니다(CORS). 이 게임은 둘 다 쓰지 않습니다. 대신 `<script src="bgm.js" defer>`, `<script src="tetris.js" defer>`로 일반 스크립트를 불러오고, 악보와 블록 모양은 코드 안에 상수로 들어 있습니다. 그래서 파일을 더블클릭해도 그대로 동작합니다.
>
> 외부에서 받아 오는 것은 **Roboto 글꼴**(Google Fonts) 하나뿐입니다. 인터넷이 없으면 시스템 글꼴로 바뀌고 게임은 그대로 동작합니다.

### A. 파일 바로 열기

**Windows + WSL에서 쓰는 경우**

1. Windows 탐색기 주소창에 아래 경로를 붙여 넣습니다. `Ubuntu-22.04`는 WSL 배포판 이름이라 PC마다 다를 수 있습니다. WSL 터미널에서 `echo $WSL_DISTRO_NAME`으로 확인하세요.
   ```
   \\wsl.localhost\Ubuntu-22.04\home\ubuntu\work\kosa-ict-genai-2026-hyundai\src\exercise\jeongju2056\day12\tetris
   ```
2. `index.html`을 더블클릭하면 기본 브라우저로 랜딩 페이지가 열립니다.

WSL 터미널에서 바로 열 수도 있습니다. 경로를 Windows 형식으로 바꿔 기본 브라우저로 엽니다.
```bash
explorer.exe "$(wslpath -w /home/ubuntu/work/kosa-ict-genai-2026-hyundai/src/exercise/jeongju2056/day12/tetris/index.html)"
```

**macOS / Linux 데스크톱:** 파일 관리자에서 `index.html`을 더블클릭하거나 브라우저 창으로 끌어다 놓습니다.

### B. 로컬 서버로 열기

Python에 들어 있는 정적 파일 서버를 씁니다. Java로 치면 톰캣 없이 정적 리소스만 내려 주는 아주 작은 웹 서버입니다.

1. 서버를 실행합니다(WSL 터미널, 어디서 실행해도 됩니다). `--directory`로 게임 폴더를 지정하고 8000번 포트로 띄웁니다.
   ```bash
   python3 -m http.server 8000 --directory /home/ubuntu/work/kosa-ict-genai-2026-hyundai/src/exercise/jeongju2056/day12/tetris
   ```
   `Serving HTTP on 0.0.0.0 port 8000 ...`이 보이면 정상입니다. 터미널은 열어 둡니다.
2. Windows 브라우저에서 접속합니다. WSL2가 `localhost`를 Windows로 자동 연결해 주므로 Windows 브라우저에서도 이 주소가 그대로 됩니다. 주소만 입력하면 `index.html`(랜딩)이 나옵니다.
   ```
   http://localhost:8000
   ```
3. 끝낼 때는 서버 터미널에서 `Ctrl + C`를 누릅니다.

서버 터미널에 `"GET /game.html?autostart HTTP/1.1" 200`처럼 요청 로그가 찍힙니다. 404가 보이면 `--directory` 경로가 틀린 것입니다.

### C. 휴대폰에서 접속하기 (같은 Wi-Fi)

WSL2 기본 네트워크(NAT)에서는 휴대폰이 WSL 안의 서버에 직접 닿지 못합니다. 그래서 **Windows가 받은 요청을 WSL로 넘겨 주는 설정**(포트 포워딩)이 필요합니다. 관리자 권한이 필요하고, 회사·학원 Wi-Fi는 기기끼리 통신을 막아 두기도 합니다. 안 되면 PC 브라우저의 개발자 도구(`F12` → 기기 툴바 `Ctrl + Shift + M`)에서 휴대폰 화면을 흉내 내 확인할 수 있습니다.

1. B의 1번처럼 서버를 띄웁니다.
2. WSL의 IP를 확인합니다(WSL 터미널). 첫 번째 값을 메모합니다. 예: `172.20.x.x`
   ```bash
   hostname -I
   ```
3. Windows **PowerShell(관리자)** 에서 Windows의 8000번 포트로 들어온 요청을 WSL로 넘깁니다. `<WSL_IP>`를 2번 값으로 바꿉니다.
   ```powershell
   netsh interface portproxy add v4tov4 listenport=8000 listenaddress=0.0.0.0 connectport=8000 connectaddress=<WSL_IP>
   ```
4. 같은 PowerShell에서 방화벽에 8000번 포트를 엽니다.
   ```powershell
   New-NetFirewallRule -DisplayName "block-stacker 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
   ```
5. Windows의 Wi-Fi IP를 확인합니다. "무선 LAN 어댑터 Wi-Fi"의 IPv4 주소를 봅니다. 예: `192.168.0.12`
   ```powershell
   ipconfig
   ```
6. 휴대폰 브라우저에서 접속합니다.
   ```
   http://192.168.0.12:8000
   ```
7. **다 쓰면 꼭 되돌립니다**(PowerShell 관리자). 포트를 열어 둔 채로 두지 않습니다.
   ```powershell
   netsh interface portproxy delete v4tov4 listenport=8000 listenaddress=0.0.0.0
   ```
   ```powershell
   Remove-NetFirewallRule -DisplayName "block-stacker 8000"
   ```

WSL의 IP는 재부팅하면 바뀝니다. 다음에 또 할 때는 2~3번을 다시 합니다.

### 문제 해결

| 증상 | 원인과 해결 |
| --- | --- |
| `OSError: [Errno 98] Address already in use` | 8000번을 이미 누가 쓰고 있습니다. 다른 번호로 띄웁니다. 예: `python3 -m http.server 8080 --directory ...` → `http://localhost:8080` |
| 화면은 나오는데 스타일이 깨짐 / 블록이 안 나옴 | HTML 파일만 따로 복사해 연 경우입니다. `base.css`, `game.css`, `landing.css`, `bgm.js`, `tetris.js`가 같은 폴더에 있어야 합니다 |
| 코드를 고쳤는데 그대로임 | 브라우저 캐시입니다. `Ctrl + Shift + R`(강력 새로고침)을 누릅니다 |
| 키를 눌러도 반응 없음 | 주소창에 포커스가 있으면 게임 화면을 한 번 클릭합니다. `game.html`을 직접 열었다면 `Enter` 또는 **게임 시작**을 먼저 누릅니다 |
| 배경음악이 안 들림 | ① 앱 바의 음표 아이콘이 꺼져 있는지(빗금) 확인하고 `M`으로 켭니다. ② 브라우저는 사용자가 클릭·키 입력을 하기 전에는 소리를 막습니다(자동 재생 정책). 그래서 랜딩에서 **플레이**로 들어오면 게임은 바로 시작하지만, 음악은 **첫 키 입력이나 터치 순간** 시작됩니다. ③ 휴대폰이 무음 모드인지, 브라우저 탭이 음소거인지 확인합니다 |
| 휴대폰에서 화면이 위아래로 밀림 | 보드 위에서는 스크롤이 막혀 있습니다. 보드 밖 여백을 밀면 페이지가 움직일 수 있으니 보드 위에서 조작합니다 |
| 최고 점수가 저장되지 않음 | 시크릿 창이거나 사이트 데이터가 차단된 경우입니다. `localStorage`는 주소(출처)별로 따로 저장되므로 `file://`과 `http://localhost:8000`의 기록도 서로 다릅니다 |
| 오류 확인 | `F12` → Console 탭에서 빨간 오류 메시지를 봅니다 |

### 배경음악 바꾸기

1. `P`(또는 재생/일시정지 버튼)로 일시정지합니다.
2. 다이얼로그의 **배경음악** 버튼에서 곡을 고릅니다(`B` 키로도 바꿀 수 있습니다).
   - **네온 스텝:** A단조, 경쾌한 8비트 (기본)
   - **광장의 춤:** D단조, 민속 춤곡풍
3. **계속하기**를 누르면 새 곡이 처음부터 나옵니다. 고른 곡은 저장되어 다음에도 유지됩니다.

## 규칙

- 보드는 10×20칸이고 블록은 7종(I O T S Z J L)입니다. 블록은 **7-bag** 방식으로 나와서, 7개마다 모든 종류가 한 번씩 등장합니다.
- 한 번에 지운 줄 수가 1·2·3·4줄이면 각각 100·300·500·800점에 현재 레벨을 곱해 더합니다.
- 10줄마다 레벨이 오릅니다. 낙하 간격은 `max(100, 1000 − (레벨−1) × 75)`ms입니다(레벨 1은 1초, 레벨 13부터는 0.1초).
- 블록이 바닥에 닿아도 0.5초 동안 이동·회전할 수 있습니다. 미루기는 최대 15회까지만 됩니다.
- **고스트**(반투명 윤곽)가 블록이 떨어질 자리를 보여 줍니다.
- 새 블록이 나올 자리가 막히면 게임 오버입니다. 최고 점수는 브라우저(`localStorage`)에 저장되고 랜딩 페이지에도 표시됩니다.
- 다른 탭으로 가면 자동으로 일시정지됩니다.
- 배경음악은 게임 중에만 나옵니다. 일시정지하면 멈춘 자리에서 이어지고, 곡을 바꾸거나 게임 오버 후 다시 시작하면 처음부터 나옵니다. 레벨이 오를 때마다 빨라집니다(곡의 기본 템포에서 레벨당 +6 BPM, 최대 200).

## 파일 구조와 "왜 이렇게 나눴나"

```
day12/tetris/
├── index.html    랜딩 페이지 (플레이 방법 + 플레이 버튼)
├── game.html     게임 화면 구조 + 아이콘 모음(SVG)
├── base.css      공통 스타일 (M3 색·모양 토큰, 버튼, 앱 바, 카드, 스낵바)
├── landing.css   랜딩 전용 배치
├── game.css      게임 전용 배치 + 반응형(휴대폰 세로·가로)
├── bgm.js        배경음악 (곡 목록 → 악보 → WebAudio 합성)
├── tetris.js     게임 로직, 그리기, 입력(키보드·버튼·스와이프)
├── PLAN.md       구현 계획
├── WORKFLOW.md   프롬프트와 결과 이력
└── README.md     이 문서
```

```
 index.html ──"플레이" 링크 (game.html?autostart)──▶ game.html
   │                                                  │
   └ base.css + landing.css                           ├ base.css + game.css
                                                      ├ bgm.js     (BGM 객체 하나만 공개)
                                                      └ tetris.js  (BGM.play/pause/stop/setTrack 호출)
```

**1) 랜딩과 게임을 다른 페이지로 나눈 이유.** 랜딩은 처음 한 번 읽는 안내문이고, 게임은 반복해서 여는 화면입니다. 나눠 두면 게임 화면은 안내문 없이 가볍게 열리고, 각 페이지의 CSS도 자기 화면만 신경 씁니다. 페이지끼리 주고받는 것은 URL의 `?autostart` 하나뿐입니다. 이 값이 있으면 게임이 바로 시작되고, 없으면(`game.html`을 직접 열면) 시작 버튼부터 나옵니다.

**2) CSS를 공통(base) + 화면별(landing/game)로 나눈 이유.** 색·둥글기·버튼처럼 두 화면이 똑같이 써야 하는 것은 `base.css` 한 곳에만 둡니다. Java로 치면 공통 부모 클래스에 두고 화면별 클래스가 상속하는 구조입니다. 색을 바꾸고 싶으면 `base.css`의 `:root` 변수만 고치면 두 화면에 모두 반영됩니다.

**3) `tetris.js` 안에서 상태와 그리기를 나눈 이유.**

```
 키보드/터치/스와이프 ──▶ [4] 게임 동작 (move, rotate, hardDrop …)
                      │  state.board / state.current 를 바꾼다   ← DB UPDATE
                      ▼
 requestAnimationFrame ─▶ update(delta)  중력·고정 처리
                      └─▶ draw()         state를 읽어 canvas에 그린다  ← SELECT 후 화면 출력
```

- `state.board`는 `int[20][10]` 2차원 배열입니다. 0은 빈칸이고 1~7은 블록 색 번호입니다. 그리기 코드는 이 배열을 **읽기만** 합니다.
- 그래서 `collides`, `rotate`, `clearLines`, `lineScore` 같은 **[3] 순수 로직** 함수는 DOM 없이도 테스트할 수 있습니다. 실제로 브라우저 없이 가짜 DOM과 가짜 AudioContext에서 82개 항목을 검사했습니다.
- 키보드·터치 버튼·스와이프는 모두 같은 `runAction('left')` 같은 함수를 부릅니다. 입력 방식이 늘어나도 로직은 그대로입니다(Controller만 추가하는 것과 같습니다).

**4) 상태 전이는 `setStatus()` 한 곳에서.** `ready → playing ⇄ paused`, `playing → over → playing`. 상태가 바뀔 때 해야 하는 일(다이얼로그 표시, 곡 선택 표시, 음악 재생·멈춤, 앱 바 아이콘)을 이 함수 하나에서 처리합니다. 여러 곳에서 `status = ...`를 직접 바꾸면 "일시정지했는데 음악은 계속 나옴" 같은 불일치가 생깁니다. Java의 상태 머신(enum + 전이 메서드)과 같은 생각입니다.

**5) 시간 기반 루프.** 중력은 "몇 프레임마다"가 아니라 "몇 ms가 지났나"(`delta`)로 계산합니다. 그래서 60Hz 모니터와 144Hz 모니터에서 같은 속도로 떨어집니다. 배치(batch) 잡에서 실행 횟수가 아니라 경과 시간으로 스케줄을 잡는 것과 같은 원리입니다.

**6) 배경음악을 `bgm.js`로 분리한 이유.** 게임은 음악의 내부를 모르고 `BGM.play()` / `pause()` / `stop()` / `setLevel()` / `toggle()` / `setTrack()`만 부릅니다(인터페이스 하나만 공개). `bgm.js` 파일이 없어도 `tetris.js`는 빈 대역 객체로 바꿔 음악 없이 돌아갑니다.

```
TRACKS[{ 곡 이름, 기본 템포, 음색, 악보 문자열 "A4:2 C5 E5 …", 베이스 근음 }]
   │ compile() (곡마다 한 번)
   ▼
timeline[128스텝] ── 25ms마다 깨어나는 스케줄러가
                     "앞으로 0.12초 안에 날 음"을 AudioContext 시계에 미리 예약
   ▼
OscillatorNode(멜로디 / 베이스) → GainNode(볼륨 곡선) → 스피커
```

- **미리 예약하는 이유:** `setInterval` 타이머는 수십 ms씩 밀릴 수 있습니다. 타이머로 직접 소리를 내면 박자가 흔들립니다. 그래서 타이머는 예약만 하고, 정확한 발음 시각은 오디오 엔진의 시계(`currentTime`)가 지킵니다. 배치 스케줄러가 다음 작업을 큐에 미리 넣어 두는 것과 같습니다.
- **일시정지:** 오디오 시계 자체를 멈춥니다(`suspend`). 재개하면 멈춘 박자부터 이어집니다.
- **곡 바꾸기:** 이미 예약된 음을 버리고(출력 노드 연결을 끊음) 다음 재생 때 새 곡의 처음부터 예약합니다.
- **곡 선택 버튼은 `bgm.js`의 곡 목록으로 만듭니다.** 곡을 추가할 때 `TRACKS`에 항목만 더하면 되고 HTML은 고칠 필요가 없습니다.
- **자동 재생 정책:** 브라우저는 사용자가 이 페이지에서 입력하기 전에는 소리를 막습니다. 그래서 `bgm.js`는 첫 키 입력·터치를 기다렸다가 AudioContext를 만듭니다(`unlock`). 랜딩에서 넘어와 게임이 자동으로 시작돼도 음악은 첫 입력 순간 시작되는 이유입니다.
- **곡:** 두 곡 모두 이 게임용으로 새로 썼습니다. 특정 게임의 대표 음악은 재현하지 않았습니다.

**7) 머티리얼 디자인을 라이브러리 없이 적용한 이유.** MUI 같은 머티리얼 라이브러리는 React와 빌드 도구가 필요합니다. 그래서 "HTML·CSS·JS만, 파일 더블클릭으로 실행"이라는 조건과 맞지 않습니다. 대신 M3 규칙을 CSS로 옮겼습니다.

| M3 요소 | 이 프로젝트에서 |
| --- | --- |
| 색 체계(color scheme) | `base.css`의 `--md-sys-color-*` 변수. M3 기본 다크 색 이름과 값을 그대로 씀 |
| 모양(shape) | 모서리 둥글기 4·8·12·16·28px 단계(`--md-shape-*`) |
| 그림자(elevation) | `--md-elevation-1`(보드·랜딩 그림), `--md-elevation-3`(다이얼로그·스낵바) |
| 상태 막(state layer) | 버튼 위 반투명 막. hover 8%, focus·pressed 10% |
| 컴포넌트 | 상단 앱 바, 아이콘 버튼(켜짐/꺼짐), 카드, 다이얼로그, 채운·톤·외곽선 버튼, 세그먼트 버튼(곡 선택), 스낵바 |
| 아이콘 | Material Icons(Apache-2.0)를 HTML 안 SVG로 넣음(외부 요청 없음) |

**8) 반응형을 만든 방법.**

| 화면 | 배치 |
| --- | --- |
| PC(600px 초과) | `[홀드·조작법] [보드] [다음·점수]` 3단 |
| 휴대폰 세로(600px 이하) | 윗줄 `[홀드] [점수 2×2] [다음]`, 가운데 보드, 아래 스와이프 안내 + 터치 버튼 4×2. 조작법 카드는 숨김 |
| 휴대폰 가로(높이 500px 이하) | 가운데 보드와 양옆 카드, 오른쪽에 터치 버튼 2열 |
| 태블릿(터치 기기) | PC 배치 + 터치 버튼 표시 |

- **HTML은 하나로 두고 CSS만 바꿉니다.** 휴대폰에서는 `.side`에 `display: contents`를 줘서, 그 안의 카드들을 바로 grid 칸(`grid-template-areas`)에 배치합니다.
- **보드 크기는 "화면 높이 − 다른 요소 높이"로 계산합니다.** `100dvh`(주소창을 뺀 실제 화면 높이)를 써서 어떤 휴대폰에서도 스크롤 없이 한 화면에 들어갑니다.
- **보드에는 `touch-action: none`을 줍니다.** 스와이프가 페이지 스크롤이나 확대로 해석되지 않게 하려는 것입니다. 노치가 있는 화면은 `env(safe-area-inset-bottom)`으로 아래 버튼을 비켜 둡니다.
- 랜딩 페이지도 900px 이하에서는 기능 카드를 2열로, 720px 이하에서는 1열로 바꾸고, 480px 이하에서는 버튼을 화면 폭만큼 넓힙니다.

## 범위 밖

효과음, 정식 SRS 킥 테이블, T-spin·콤보 점수, 멀티플레이, 온라인 랭킹, 밝은 테마, 기존 게임 음악 재현은 넣지 않았습니다.
